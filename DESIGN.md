# LingoMage design

## Reference and visual language

Follow the App² starter template and host slate palette. The reference is App²'s `app/src/main/assets/starter_template/css/style.css` and native `res/values/colors.xml`. Keep LingoMage's blue reading accents within that shared visual language. This document describes the current design; it does not establish usability or learning effectiveness.

Use the shared CSS tokens: `--paper` (#090d16), slate reader surface (#0f172a), `--card`, `--line`, `--field`, `--ink`, `--muted` (#94a3b8), `--accent`, and `--accent-strong` (#3b82f6). Use 18px card corners, 12px field/button corners, subtle borders and restrained elevation. Avoid introducing a separate reader color theme.

## Interface copy and visual cues

Use interface text for information learners need to decide or recover: what happened, what content is preserved, what an action will do, and any consequence or requirement they cannot infer from the control. Use concise labels that name the action or content. Add helper text when it resolves an actual ambiguity; omit instructions that merely describe an obvious control.

Show familiar interaction mechanics visually. A labelled expandable section uses a downward chevron when collapsed and an upward chevron when expanded. “Technical details” plus this state cue replaces “Open Technical details for the information supplied by the service.” Keep the error summary focused on the failure and saved progress; let the disclosure reveal diagnostics on demand.

Visual cues supplement accessible labels and semantic state. Use native disclosure behavior or equivalent keyboard operation and announced expanded/collapsed state. Do not rely on a chevron, color or icon alone to communicate an action, error cause, destructive consequence or unavailable feature. Keep the cue near its label and make the whole control a touch target of at least 44px.

Before adding explanatory copy, ask whether a clearer label, visible state, spacing or familiar symbol would communicate the same interaction. Keep words when they explain meaning or consequences; use a visual cue when it explains how a familiar control behaves. This convention follows the learner’s feedback on generation recovery (2026-10-14): an instruction to open Technical details was redundant, and a collapsed/expanded chevron made the disclosure's behavior visible; it is a product preference, not a measured usability finding.

## Layout and controls

Create leads with one optional multiline Story idea and topics field (premise, genre, tone or format, plus domains, communication situations, concepts or expressions), then Reading scope, then Language and Reading level. Keep the learning-preferences setup notice beside the language fields. These story-first choices are product assumptions.

Keep the mobile-first Create, Library and Profile navigation (Settings is reached from Profile) with icons above labels, matching the App² starter. Reserve space for the bottom bar and combine host and browser safe-area insets. Controls have at least 44px touch targets, visible keyboard focus and English accessible labels. Respect reduced motion. Use shared button and field classes instead of feature-specific replacements.

The reader is full-screen, with a centered column no wider than 780px and no top bar. Use the story title, with Listen vertically centered beside the title, then one compact row of Previous, Chapter picker, Next and Aa controls, centered within the reader column. The bottom row sticks at the top safe area as the expanded title scrolls away; scrolling back restores the full card without a layout jump. Chapter/path navigation and reading preferences open floating panels without adding permanent rows. Android Back returns to the Library while the reader is open. Give canonical story text comfortable line spacing and keep Japanese readings as separate annotations. Glossary forms have a subtle underline and open a small anchored note on tap or keyboard activation; note controls must keep story text selectable. The note is a labelled nonmodal dialog popover with a 44px Listen icon beside each headword. Opening focuses the popover; Escape returns focus to its trigger. Listen speaks the canonical displayed headword, excluding readings, through App² speech with the story locale. Browser previews disable Listen with an App² availability explanation. Beneath the story, place equal-width Continue story and Rewrite chapter buttons, then the prompt panel when opened, then one Explanations section with saved cards newest first. Story deletion is available from the Library, rather than the reader.

Disable spelling correction only on the canonical reader story body and title with `spellcheck="false"`. Editable fields retain normal spelling suggestions and editing menus; do not disable correction on surrounding reader containers. Android correction-menu behavior requires device verification.

Text is unselectable by default (`user-select: none` on `body`); selection is opt-in. Selectable with the LingoMage toolbar (native Android menu suppressed): the reader story body and title. Selectable with the native Android menu: inputs, textareas, contenteditable, explanation-card text (`.help-text-selectable`), the vocabulary note popover and `.form-error` text. Unselectable: app title, headlines, labels, helper and instruction text, buttons, tab bar, story cards, confirm dialogs and toasts. `js/selection-menu.js` toggles the page-wide host flag by touch target (`pointerdown`), by selection location (`selectionchange`, so handle drags and keyboard selections route too), on field focus and on reader entry. A selection touching story or title text always uses the LingoMage toolbar. The last value is cached only after the host acknowledges it, so a rejected or unavailable host is asked again on the next event. Only the `contextmenu` event on story and title text is cancelled; selection gestures (`pointerdown`, `touchstart`, `selectstart`) are never prevented, and fields, explanation text, notes and errors keep their native menu. Rationale: opt-in avoids half-working selection (handles but no menu) on chrome text; errors stay selectable so users can copy them for bug reports. Fields must set `user-select: text` explicitly because a `none` body default can break caret placement in some Android WebViews. Android menu behavior requires device verification.

Selecting text offers Translate, Explain and a leading Speak speaker icon in the LingoMage toolbar. The Speak icon uses the shared icon-button styling and an accessible “Speak selected text” label. Speak uses canonical selected text and the story locale through the existing App² speech wrapper; browser previews disable it with an availability explanation. The toolbar also carries Copy; Speak uses the selected text’s language and Android’s configured voice. Keep the Explain toolbar available in every environment. Stop native playback when the reader closes or its chapter/version changes.

Every selection-toolbar action uses the shared transient action state (`runSelectionAction`): show its active highlight and accessible busy state only until that action's own completion point. Copy ends when clipboard writing completes, Translate when the device translator opens, Explain when its AI task starts (not when generation finishes), and Speak when selected-text playback finishes. Future selection-toolbar actions must use the same runner and define their completion point. Buttons highlight immediately while pressed, including on touch, and activate on release; cancelled presses do not activate. Keyboard focus remains visually distinct from the action highlight. Successful Copy clears selection and dismisses the toolbar; rely on Android’s existing clipboard confirmation without adding an app toast. Failure retains selection and the toolbar and shows an app error.

Long-press the non-text surface of a saved explanation card to select it; text inside the card remains available for native selection and context menus. Padding and gaps are selection surfaces. Use compact checkbox marks in 44px touch targets, a floating bottom bar with selection count, trash control and a mixed-state checkbox. The checkbox shows a minus for partial selection; activating it selects all explanations in the displayed chapter version. When all are selected it shows a checkmark; activating it clears selection and exits. Keep the bar centered within the reader, 12px above the bottom safe area, and reserve bottom scrolling space for the final card. The library selection toolbar retains its existing behavior. Tapping a non-text card surface or checkbox toggles it; text remains selectable while selection mode is active. Clearing the last selection exits the mode. Hide follow-up actions while selecting. Provide a keyboard-accessible Select explanation control on focus and let Escape exit selection. Preserve scroll position and focus as selection changes. Deleting selected explanations also removes their attached follow-ups.

In the Library, open a story with a normal tap and enter bulk selection with a long press or a story's visible Actions button (Select, Delete). Show compact checkbox marks in 44px touch targets and a sticky selection toolbar in that mode; the hero and rows show checkboxes in place of Actions, and sorting is disabled. Remove the global Select stories button and any permanently visible per-card delete control. The trash button opens an app-styled confirmation that names the selected story count and warns that chapters, versions and explanations are removed. Cancel preserves selection. Tapping a story card toggles it while selection is active; clearing the last selection exits the mode. These interaction choices are product assumptions, not evidence of usability or learning effects.

Selection checkboxes have 44px touch targets. Cancel a pending long press when the pointer leaves the card, moves beyond the hold threshold, is released or cancelled, or the page scrolls.

## Selection help and follow-ups

Explain acts on the exact canonical selection. Group saved cards under one Explanations heading, with separate bordered cards and an accent rule marking the relevant source excerpt. The model chooses a contiguous source excerpt and the app highlights only the user’s exact selection. Context translations are optional and appear beneath the excerpt when useful. Initial help is one short paragraph. English help uses the interface font; story text keeps its reading typography. Wrap long content without horizontal scrolling. Keep saved explanations visible while a request runs. Show a compact, cancellable loading panel above the cards for initial help and inside the matching card for details and examples; retain the question after a failed detail request. Examples remain inside their explanation card, separated by a divider.

Keep clear vertical spacing between explanation actions and any loading, error, or recovery content inserted into the same card. Continuation and rewrite show the same compact status-card style beneath the edit panel, with an action-specific heading and Cancel request. The card appears from request preparation through completion and follows its initiating story when the reader changes. Keep the current chapter visible, disable editing during generation, retain failed prompts, and preserve explicit save/release recovery.

More detail reveals a labelled, one-line, optional question field with Cancel and More detail. Opening or cancelling the field must not request AI. Enter submits; an empty question requests general detail on the same selection. Display each submitted question with its saved follow-up response. Detail responses remain text in storage and appear as saved follow-ups with paragraphs, bold, italic and inline code rendered using DOM elements and text nodes. Unsupported formatting and HTML remain literal; Generate examples directly requests three short examples of the same contextual function. Each example shows a highlighted relevant form and an English translation under an Examples heading. Both actions remain available; additional follow-ups append in order. Use text nodes for all learner and model content. Keep request cancellation and explicit save/release retry controls available.

## Verification

Every interface or copy change requires a visual screenshot inspection at desktop and narrow mobile widths before completion. Verify spacing, wrapping, hierarchy, clipping and touch targets, including loading/error states when affected. A passing DOM or automated functional check does not verify layout quality. Record the screenshots/layouts actually inspected and any remaining device-only checks.

Keep helper copy concise and visually grouped with its field: a 6px field-to-helper gap and a 22px gap after each complete Create field group. Labels, controls and helpers share a group; generic field bottom margins must not push helpers toward the next label. Textareas need internal vertical padding.

Check desktop and narrow mobile layouts, visible furigana, large reading text, keyboard focus, disclosures and follow-up submission in the deterministic development server. Mock checks establish UI behavior only. Host insets, Android keyboard and selection behavior require App² device verification.

Library structure (navigation conventions and product assumptions; they do not indicate progress, completion, comprehension or learning effect). The tab and page are titled **Library**; the page shows a count under the title ("7 stories", or "2 of 7 stories" when filtered) and a compact **Sort stories** select on that row, which wraps below on narrow screens. Language chips (All plus the languages present) scroll inside their own row and are hidden when only one language exists; a filter that no longer matches any story returns to All. The first card is the **hero**, the story with the latest meaningful saved activity (eyebrow "Latest activity · Language"), independent of the optional sort, and the only emphasized card: a soft accent tint and a decorative "Read ›" pill (48px high, at least 96px wide, existing accent token, hidden from assistive technology and during selection) sit inside the same card, which stays one control. There is no separate newest-created shortcut; a story just created is the hero until other activity is saved. Every other story appears exactly once under "More stories", in the chosen sort. Sort is session-only (resets on reload) and offers only **Recent activity** (default) and **Newest created**. Cards show up to two title lines, the language and a date line; prompts, practice words and topics are not shown. Never label a story Continue, In progress, Completed, Last studied or Progress. Date copy uses the local calendar: Today, Yesterday, "N days ago" (2–6), then "17 Oct" (with the year in another year), in semantic `<time>` elements; the accessible name spells out "Updated" and "Created" with full dates. The hero shows only its relevant date ("Updated 2 days ago", or "Created …" without a later update), with a wrapping footer, 14px separation from the title and 18px card padding; both full dates remain in its accessible name. Recent-activity rows "Updated …" (or "Created …" when no later activity exists), Newest-created rows "Created 12 Oct". "Updated" is shown whenever the saved activity instant is later than the creation instant, even on the creation day; calendar days are never compared to hide it. A newly created story, including one finished later by a resumed or recovered request, reads "Created" (its creation save counts as activity for ranking, not as an update). Invalid or missing dates omit that segment. If no story has any valid date the first story is a plain hero without latest wording. After a background save re-renders the list, focus returns to the rebuilt Actions button of the story whose popover was open. Empty library: one "No stories yet" state. A single story shows only the hero and no list label.

Each card has a visible 44px Actions button beside (not nested in) the open control. There is no swipe gesture or tray. Actions opens a fixed popover labelled "Actions for <title>", a group of native Select and Delete buttons (no `role=menu`), right-aligned under the button and flipped above it near the bottom bar. Focus moves to Select; Escape closes it and returns focus to the button; outside press, scroll, resize, focus leaving, filter, sort, opening a story or bulk selection also close it. Delete opens the app-styled confirmation naming the story and warning that all chapters, versions and explanations are permanently removed; Cancel receives initial focus and focus returns to the Actions button. No undo is offered. A request that completes in the background re-renders a visible Library, but never while a selection or popover is open; the list updates when it ends. These interaction choices are product assumptions.

Continuation and rewrite prompt labels show optional. Blank continuation follows the existing narrative; blank rewrite creates a fresh telling of the same main events. Keep concise placeholders explaining that ideas may be multilingual or blank. Settings helpers and examples are brief, with 6px to their field and 22px before the next labelled field; reading-band summaries retain Japanese kana and Russian Cyrillic prerequisites.

Create shows one brief language-input note inside the Story idea and topics group, between its label and the textarea: “Write in English, your learning language, or a mix.” The story field references it for accessibility. Story idea and topics gently invites writing in the learning language. Chapter prompt placeholders also allow ideas in any language or a blank submission. Avoid repeating the note under each field or implying that these inputs provide writing corrections.


Story paths preserve alternate histories. Show a labelled Story path selector above chapter navigation only when more than one path exists; name paths Original and Alternate N. Chapter navigation contains only that path's pinned versions. Rewriting switches to a new path ending at the rewritten chapter and preserves the source path's later chapters. Show the fork chapter and source path beneath navigation. Continue appends after the selected path's ending even when an earlier chapter is displayed. Keep reading positions separately per path. Save them with the story in `data/stories.json` when the reader closes or the page is hidden, so reopening a story after a restart returns to the last chapter and scroll offset. Disable path switching during generation; navigation within the path may remain available. Preparing story context uses the existing cancellable status card before chapter generation. Retain the prompt and completed memory checkpoints after cancellation or failure. These interaction choices are product assumptions.


Story actions is a kebab menu in the title section, available with one or multiple paths. It contains Continue story, Rewrite chapter and Copy chapter, then Remove Chapter N onward (or Remove Chapter N for the final chapter), plus Delete this path when alternatives exist or Delete story for the sole path. The disclosure is keyboard accessible; Escape closes it and restores focus. Scroll, resize, outside interaction and chapter changes dismiss it. Pending AI work or unsaved/unreleased results disable destructive actions with a short explanation.

Removal uses app-styled confirmation with Cancel initially focused. Name the selected path and exact chapter range, explain preservation on other paths, and warn that exclusively unused content is permanently deleted. Chapter 1 removal deletes that path; removing the only path uses whole-story confirmation. Successful truncation displays the preceding chapter; deleting a path opens the oldest remaining path at its beginning, preserving its name. Hide the path selector when only one path survives. Keep confirmations available on failed saves with an inline retry explanation. These choices are product assumptions; no trash or undo is offered.

## Generation recovery — 2026-10-14

Create displays one checkpoint recovery panel immediately above Generate, retaining its captured brief, language, level and scope after reload. Checkpoint failures do not also appear as a separate red form error. Chapter recovery follows the edit panel; example recovery follows Explanations; explanation and detail failures offer Retry beside their source content or question. The reader status bar offers View recovery for actual failures and keeps its wording brief. Intentional explanation/detail cancellation removes loading and generation status, preserves existing explanations and the follow-up question, and briefly confirms “Request cancelled”; it offers no recovery. If releasing the cancelled host request fails, the status instead says “Could not finish cancelled request” with Finish request, which only retries cleanup. Recovery scrolling accounts for fixed status bars, which have no offset parent, and bottom navigation.

Use a wrapping flex action row with a 12px gap and 44px minimum targets. Summaries identify the action, failed stage when known, and preserved content. Technical details use a keyboard-accessible disclosure with a downward chevron when closed and an upward chevron when open with bounded, redacted error text and an available host error code. An unidentified service failure remains unidentified. Retry explicitly requests a failed stage; Resume continues saved progress; Save response saves completed content; Finish request retries release without inference. Incompatible saved definitions explain why Discard is required. These are interface choices, not validated usability or learning-effectiveness claims.

Settings is a separate view reached from the Profile gear (see Profile). It holds one card under a small uppercase section label, Story writer (AI model and Reasoning effort, each with a one-line helper; the reasoning helper hides with its field), a “‹ Back to Profile” button (44px) above its heading, and one centered footer note, “Saved on this device automatically.” Reader preferences stay in the reader; the App² update control is not yet in the interface and belongs here when added. Language controls live in Profile under My languages, with the same behavior: it has two groups. Learning lists enabled languages as rows with the name, a level summary (or “Choose a reading level”) and a wide 48px tinted stroked chevron; the whole header toggles Reading level and Language preferences (optional), which end with a red Stop learning text button that keeps saved settings. Add a language lists the remaining targets as dashed rows with “+ Add”; adding expands the new row, and the group hides when every language is enabled. A helper states that Create offers languages in this order, starting with the first. When more than one language is enabled, each row shows a left grip handle (44px, touch-action none): dragging collapses the rows, lifts the held row and shifts the others, near-edge dragging scrolls, release saves and Escape or cancel restores. The focused grip also reorders with Arrow Up/Down and announces the new position; there are no position numbers or Move buttons. Order saves as the full language sequence and applies to enabled languages in Create (or all when none are enabled). These are product preferences, not measured usability findings.

While a chapter is read aloud, a listening player floats under the sticky Previous/Chapter/Next/Aa row. App² leaves playback controls to the app by default. A zero-height sticky anchor holds it, and the story reserves 68px once when playback starts so the first lines are not covered. Collapsed it is a pill at most the column width (286px at 320px): Previous sentence, Pause/Resume (filled accent), Next sentence, "n / total", Stop and an expand chevron, each a 44px target. Expanded it spans the column with a sentence slider, a native speed select and a Follow toggle, and collapses after 5 seconds without interaction or on a tap in the text. The spoken sentence uses the CSS Custom Highlight API (`::highlight(speaking)`), so DOM, canonical offsets, furigana and copy are unchanged; hosts without it keep the controls. Follow keeps the sentence below the player and turns itself off for that playback on a manual wheel or touch scroll without changing the saved preference. Listening speed and Follow persist in `data/settings.json` readingPreferences. The player is a labelled group with Pause/Resume and expanded states exposed; sentence position is announced politely only after Previous, Next or the slider. Motion respects reduced-motion preferences. Title-card Listen starts playback and, while it plays, stops it. These layout choices are product assumptions.

## Workspace recovery and scaling

Allow browser pinch/zoom across the entire interface; the reader text-size control remains an independent preference. At enlarged text and narrow widths, recovery content and controls must wrap and remain reachable without horizontal page scrolling. Browser scaling checks do not establish Android font scaling or TalkBack behavior.

A persistent Workspace needs attention panel precedes the active view when stories, settings or checkpoints cannot be read safely. Its selectable English message names the file and states that the original is preserved. Retry loading explicitly reloads after external repair; the app never offers an automatic reset. Block generation and settings edits while a required store is invalid, but keep intact stories readable. Profile languages and Settings stay readable while a store is unreadable: disclosure toggles work, editing controls are disabled (practice period and gear remain usable). Recovery uses existing panel/button styles, visible keyboard focus and 44px targets.

Preference save failures are separate from unreadable stores. A failed write restores every affected control to the saved value (text size, Furigana, Listening speed, Follow, model and its Reasoning options, language rows) without moving keyboard focus or discarding text typed in a Language preferences field, and shows a persistent “Preference not saved” notice. The reader is modal, so the notice appears inside it, fixed above the safe area and any generation bar, with measured bottom scroll space so the final chapter actions remain reachable, and in the page when the reader is closed; only the visible copy is a live alert, and the reader copy goes away when the reader closes. The notice names the file, says the previous settings still apply and offers Retry save, which repeats the intended change (never a reload); a later failure of the same kind does not rebuild or re-announce it. When settings are unreadable the notice offers no Retry save and tells the learner to close the reader and use Retry loading. Retry loading reloads the page only when no AI request, unsaved response or unsaved preference would be lost; otherwise it says what to finish first. Unrelated preference saves never rebuild checkpoint recovery panels. These are product choices, not usability findings.

## Profile

Profile is the third bottom-navigation tab (Create, Library, Profile; the tab bar stays 44px+ at 320px). It is one scrollable page with a plain Profile heading (no eyebrow, avatar, name or identity banner) and a 48px gear icon button labelled “Settings” that opens the separate Settings view; Profile stays the current tab there and Back to Profile returns focus to the gear. Order: checkpoint recovery (when present), My practice, My languages (the editable language list, order, levels and preferences described under Settings; the Create setup prompt’s Open Profile button scrolls to it). My practice is compact: the shared period radiogroup (Today, Last 7 days, All time; arrow keys move and select, 44px targets) sits above one card with the Time in LingoMage total, then By language rows and a final By activity row. Each is a full-width disclosure button (44px, `aria-expanded`, `aria-controls`, chevron; native Enter and Space) that is collapsed by default: a language row reveals that language’s activity rows, and By activity reveals the period’s activity totals, so no figure is dropped and no one-row card repeats information. Open keys persist across period changes and refreshes. When a rebuild replaces the content, focus returns to the same row; if that row no longer exists in the new period, focus moves to the selected period so it is never lost to the page. Section spacing is tightened (8–14px) so My languages starts sooner. Time labels are factual durations, not learning progress. Durations are human text (“Less than 1 minute”, “1 hour 5 minutes”), with no charts, goals, reset or export. Languages that are disabled or whose stories were deleted still appear while they have history. The empty state, explaining that time appears after use and earlier use is not counted, shows only when no time has been recorded; any positive total under a minute reads “Less than 1 minute”. The figures refresh while visible without moving focus: the content is not a live region and is replaced only when its text changes. An unreadable or unsaved usage file shows an amber notice above the periods (Retry loading or Retry save, announced once per state change); it never blocks other screens. Counting rules and limits are in `docs/architecture/app2-runtime.md`. These are product choices, not usability findings.
