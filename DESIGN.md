# LingoMage design

## Reference and visual language

Follow the App² starter template and host slate palette. The reference is App²'s `app/src/main/assets/starter_template/css/style.css` and native `res/values/colors.xml`. Keep LingoMage's blue reading accents within that shared visual language. This document describes the current design; it does not establish usability or learning effectiveness.

Use the shared CSS tokens: `--paper` (#090d16), slate reader surface (#0f172a), `--card`, `--line`, `--field`, `--ink`, `--muted` (#94a3b8), `--accent`, and `--accent-strong` (#3b82f6). Use 18px card corners, 12px field/button corners, subtle borders and restrained elevation. Avoid introducing a separate reader color theme.

## Layout and controls

Create leads with one optional multiline Story idea and topics field (premise, genre, tone or format, plus domains, communication situations, concepts or expressions), then Reading scope, then Language and Reading level. Keep the learning-preferences setup notice beside the language fields. These story-first choices are product assumptions.

Keep the mobile-first Create, My stories and Settings navigation with icons above labels, matching the App² starter. Reserve space for the bottom bar and combine host and browser safe-area insets. Controls have at least 44px touch targets, visible keyboard focus and English accessible labels. Respect reduced motion. Use shared button and field classes instead of feature-specific replacements.

The reader is full-screen, with a centered column no wider than 780px and no top bar. Use the story title, then separate chapter/path navigation from text-size and furigana controls, letting the groups wrap on narrow screens. Android Back returns to My stories while the reader is open. Give canonical story text comfortable line spacing and keep Japanese readings as separate annotations. Glossary forms have a subtle underline and open a small anchored note on tap or keyboard activation; note controls must keep story text selectable. The note is a labelled nonmodal dialog popover with a 44px Listen icon beside each headword. Opening focuses the popover; Escape returns focus to its trigger. Listen speaks the canonical displayed headword, excluding readings, through App² speech with the story locale. Browser previews disable Listen with an App² availability explanation. Beneath the story, place equal-width Continue story and Rewrite chapter buttons, then the prompt panel when opened, then one Explanations section with saved cards newest first. Story deletion is available from My stories, rather than the reader.

Disable spelling correction only on the canonical reader story body and title with `spellcheck="false"`. Editable fields retain normal spelling suggestions and editing menus; do not disable correction on surrounding reader containers. Android correction-menu behavior requires device verification.

Text is unselectable by default (`user-select: none` on `body`); selection is opt-in. Selectable with the LingoMage toolbar (native Android menu suppressed): the reader story body and title. Selectable with the native Android menu: inputs, textareas, contenteditable, explanation-card text (`.help-text-selectable`), the vocabulary note popover and `.form-error` text. Unselectable: app title, headlines, labels, helper and instruction text, buttons, tab bar, story cards, confirm dialogs and toasts. `js/app.js` toggles the page-wide host flag on `pointerdown` using `NATIVE_MENU_SELECTOR`. Rationale: opt-in avoids half-working selection (handles but no menu) on chrome text; errors stay selectable so users can copy them for bug reports. Fields must set `user-select: text` explicitly because a `none` body default can break caret placement in some Android WebViews. Android menu behavior requires device verification.

Selecting text offers Translate, Explain and a leading Speak speaker icon in the LingoMage toolbar. The Speak icon uses the shared icon-button styling and an accessible “Speak selected text” label. Speak uses canonical selected text and the story locale through the existing App² speech wrapper; browser previews disable it with an availability explanation. The toolbar also carries Copy; Speak uses the selected text’s language and Android’s configured voice. Keep the Explain toolbar available in every environment. Stop native playback when the reader closes or its chapter/version changes.

Long-press the non-text surface of a saved explanation card to select it; text inside the card remains available for native selection and context menus. Padding and gaps are selection surfaces. Use compact checkbox marks in 44px touch targets, a floating bottom bar with selection count, trash control and a mixed-state checkbox. The checkbox shows a minus for partial selection; activating it selects all explanations in the displayed chapter version. When all are selected it shows a checkmark; activating it clears selection and exits. Keep the bar centered within the reader, 12px above the bottom safe area, and reserve bottom scrolling space for the final card. The library selection toolbar retains its existing behavior. Tapping a non-text card surface or checkbox toggles it; text remains selectable while selection mode is active. Clearing the last selection exits the mode. Hide follow-up actions while selecting. Provide a keyboard-accessible Select explanation control on focus and let Escape exit selection. Preserve scroll position and focus as selection changes. Deleting selected explanations also removes their attached follow-ups.

On My stories, open a story with a normal tap and enter bulk selection with a long press or the visible per-story Actions button (Select, Delete). Show compact checkbox marks in 44px touch targets and a sticky selection toolbar in that mode; remove the global Select stories button and any permanently visible per-card delete control. The trash button opens an app-styled confirmation that names the selected story count and warns that chapters, versions and explanations are removed. Cancel preserves selection. Tapping a story card toggles it while selection is active; clearing the last selection exits the mode. These interaction choices are product assumptions, not evidence of usability or learning effects.

Selection checkboxes have 44px touch targets. Cancel a pending long press when the pointer leaves the card, moves beyond the hold threshold, is released or cancelled, or the page scrolls.

## Selection help and follow-ups

Explain acts on the exact canonical selection. Group saved cards under one Explanations heading, with separate bordered cards and an accent rule marking the relevant source excerpt. The model chooses a contiguous source excerpt and the app highlights only the user’s exact selection. Context translations are optional and appear beneath the excerpt when useful. Initial help is one short paragraph. English help uses the interface font; story text keeps its reading typography. Wrap long content without horizontal scrolling. Keep saved explanations visible while a request runs. Show a compact, cancellable loading panel above the cards for initial help and inside the matching card for details and examples; retain the question after a failed detail request. Examples remain inside their explanation card, separated by a divider.

Keep clear vertical spacing between explanation actions and any loading, error, or recovery content inserted into the same card. Continuation and rewrite show the same compact status-card style beneath the edit panel, with an action-specific heading and Cancel request. The card appears from request preparation through completion and follows its initiating story when the reader changes. Keep the current chapter visible, disable editing during generation, retain failed prompts, and preserve explicit save/release recovery.

More detail reveals a labelled, one-line, optional question field with Cancel and More detail. Opening or cancelling the field must not request AI. Enter submits; an empty question requests general detail on the same selection. Display each submitted question with its saved follow-up response. Detail responses remain text in storage and appear as saved follow-ups with paragraphs, bold, italic and inline code rendered using DOM elements and text nodes. Unsupported formatting and HTML remain literal; Generate examples directly requests three short examples of the same contextual function. Each example shows a highlighted relevant form and an English translation under an Examples heading. Both actions remain available; additional follow-ups append in order. Use text nodes for all learner and model content. Keep request cancellation and explicit save/release retry controls available.

## Verification

Every interface or copy change requires a visual screenshot inspection at desktop and narrow mobile widths before completion. Verify spacing, wrapping, hierarchy, clipping and touch targets, including loading/error states when affected. A passing DOM or automated functional check does not verify layout quality. Record the screenshots/layouts actually inspected and any remaining device-only checks.

Keep helper copy concise and visually grouped with its field: a 6px field-to-helper gap and a 22px gap after each complete Create field group. Labels, controls and helpers share a group; generic field bottom margins must not push helpers toward the next label. Textareas need internal vertical padding.

Check desktop and narrow mobile layouts, visible furigana, large reading text, keyboard focus, disclosures and follow-up submission in the deterministic development server. Mock checks establish UI behavior only. Host insets, Android keyboard and selection behavior require App² device verification.

On My stories, each card has a visible 44px Actions kebab and a swipe gesture; both reveal the same 168px full-height tray with two labelled actions, Select (slate, check icon) and Delete (red, trash icon), each at least 44px. The entire padded slate reading surface slides over the tray, keeping the card corners clipped; the surface must be opaque (not the translucent card token) so the tray never shows through while sliding; do not move text alone. The surface follows the finger one-to-one (clamped to the tray width) and settles open when released after a leftward swipe of at least 60px, or closed after a rightward swipe of at least 60px or a shorter drag. Recognize horizontal intent only when horizontal movement exceeds vertical movement by 1.5×; preserve vertical scrolling and cancel long press during a swipe. Mouse dragging uses the same gesture. The Actions button opens the tray and focuses Select; Escape closes it and returns focus to the button. Only one card is open; a rightward swipe, outside tap, Escape, opening a story, filter change or bulk selection closes it. Delete opens the app-styled confirmation naming the story and warning that all chapters, versions and explanations are permanently removed; Cancel receives initial focus. No undo is offered: single and bulk deletion keep the confirmation because one story can hold many chapters and explanations. The visible Actions button replaces the earlier gesture-only deletion and hidden focus-only Select control; no first-run swipe hint is shown. These interaction choices are product assumptions.

Continuation and rewrite prompt labels show optional. Blank continuation follows the existing narrative; blank rewrite creates a fresh telling of the same main events. Keep concise placeholders explaining that ideas may be multilingual or blank. Settings helpers and examples are brief, with 6px to their field and 22px before the next labelled field; reading-band summaries retain Japanese kana and Russian Cyrillic prerequisites.

Create shows one brief language-input note inside the Story idea and topics group, between its label and the textarea: “Write in English, your learning language, or a mix.” The story field references it for accessibility. Story idea and topics gently invites writing in the learning language. Chapter prompt placeholders also allow ideas in any language or a blank submission. Avoid repeating the note under each field or implying that these inputs provide writing corrections.


Story paths preserve alternate histories. Show a labelled Story path selector above chapter navigation only when more than one path exists; name paths Original and Alternate N. Chapter navigation contains only that path's pinned versions. Rewriting switches to a new path ending at the rewritten chapter and preserves the source path's later chapters. Show the fork chapter and source path beneath navigation. Continue appends after the selected path's ending even when an earlier chapter is displayed. Keep reading positions separately per path within the page session. Disable path switching during generation; navigation within the path may remain available. Preparing story context uses the existing cancellable status card before chapter generation. Retain the prompt and completed memory checkpoints after cancellation or failure. These interaction choices are product assumptions.


Story actions is a kebab menu in the title section, available with one or multiple paths. It contains Continue story, Rewrite chapter and Copy chapter, then Remove Chapter N onward (or Remove Chapter N for the final chapter), plus Delete this path when alternatives exist or Delete story for the sole path. The disclosure is keyboard accessible; Escape closes it and restores focus. Scroll, resize, outside interaction and chapter changes dismiss it. Pending AI work or unsaved/unreleased results disable destructive actions with a short explanation.

Removal uses app-styled confirmation with Cancel initially focused. Name the selected path and exact chapter range, explain preservation on other paths, and warn that exclusively unused content is permanently deleted. Chapter 1 removal deletes that path; removing the only path uses whole-story confirmation. Successful truncation displays the preceding chapter; deleting a path opens the oldest remaining path at its beginning, preserving its name. Hide the path selector when only one path survives. Keep confirmations available on failed saves with an inline retry explanation. These choices are product assumptions; no trash or undo is offered.


## Standardized reading targets — PED-004

Settings use one Reading level dropdown per enabled language with an English reading-task description; omit the knowledge textarea and retain Language preferences. New targets have an unselected placeholder. CEFR display names are explanatory shorthand; JLPT and TORFL have language-specific labels. Create uses the same level options plus Reading scope as a two-option side-by-side segmented radio group (Scene, Chapter; each segment at least 44px tall), default Scene, with a one-line helper that updates with the selection. Saved stories or versions that used the retired Longer passage scope open as Chapter. Continue/Rewrite expose version-level target and scope. Field helpers remain 6px below their fields with 22px between groups. Disabled reader fields cannot change during generation.

Show Planning suitable language and Writing your story as separate progress states. Saved checkpoint progress offers Resume / Save / finish and Discard from Create, Settings and its originating reader. Freeze its inputs; changing controls cannot alter it. Recovery actions wrap with 44px touch targets. No reader-feedback or automatic level-advancement controls are present. These conventions are product choices, not validated learning or usability claims.

Inline glossary links appear only at the first eligible occurrence of each normalized headword/English-meaning pair in the displayed chapter version. Later occurrences stay selectable for Explain. Alternate forms share a note; different meanings remain separate. Reopening, switching chapters or switching versions recomputes links deterministically. Japanese matches spanning ruby/plain segments retain full readings, share the same popup and expose only the first fragment as a keyboard button. All fragments activate that primary control; closing the popup restores its focus. See PED-002 for the product assumption and evidence limits.
Reader AI requests also show a floating bottom status bar for explanations, details, examples, continuation and rewrite. Keep it above safe-area insets, reserve scrolling space and lift selection toolbars above it. Show Cancel request during inference and a persistent Ready / View result after saving and releasing the request. View result opens the originating chapter/version and scrolls to its explanation or chapter heading. Do not scroll to loading content automatically. Errors remain dismissible; save and release failures retain explicit recovery actions. Status follows its initiating story. These interaction choices are product assumptions.

Translate opens the configured device translation handler after a deliberate tap, forwarding only canonical selected text. The external tool chooses source and target languages; English output is not guaranteed. Check translation availability when selection shows the toolbar or changes the selected passage, without startup or post-launch checks. Cache confirmed availability; temporary check failures preserve it and stale/background responses are ignored. Disable Translate before availability is confirmed, when no handler is confirmed, or while a launch is pending. Show launch errors without retrying automatically.

The reader title section's labelled Listen to chapter button (speaker icon plus text) reads the complete displayed chapter's canonical story text in its story locale, excluding title, furigana, glossary and explanations. Long chapters play as sequential bounded utterances. Native Stop, replacement speech, reader closure and chapter/version changes interrupt playback; never resume subsequent chunks after cancellation. Browser previews disable Listen with the existing App² availability explanation.

Japanese ruby readings belong above contiguous kanji runs, with compounds kept together. Written kana, okurigana and punctuation remain plain canonical text. Normalize legacy mixed annotations for display only when their readings align uniquely; preserve original data and avoid guessing ambiguous pronunciations.

Narrative scope uses Scene/Chapter segmented choices in Create and reader edits, independent of the standardized reading target. Numerical word/sentence quotas and the Settings length slider are retired. Checkpoint recovery shows planning, prose and readings status; offer Cancel during inference and Resume / Save / finish plus Discard when idle. Never expose partial prose as completed reading material.

Reader text selection shows a compact floating popover (dark card, 14px radius, soft shadow, 44px targets) centered above the selected text and clamped to the viewport. When there is no room above it moves below the selection, with extra clearance on touch devices so it does not cover native selection handles. It repositions on scroll and resize. Actions are a Speak icon button first, then Translate and Explain as text labels, then a Copy icon button (accessible labels “Copy selected text” and “Speak selected text”). Select all is removed; Copy chapter lives in the Story menu and copies the displayed chapter's canonical text, without title or furigana. The app has a dark theme only, so the popover follows it. These interaction choices are product assumptions.

Reader checkpoint recovery belongs below the edit panel, beside chapter request status, rather than above the title. Failed checkpoints offer Retry (or Save / finish for completed stages) and Discard; error copy explains rejected AI output and points to these controls.


Chapter generation shows Planning suitable language, Writing your story, Adding vocabulary notes and (for Japanese) Adding kanji readings as separate progress messages. Active reader requests use their existing chapter status card without a duplicate checkpoint card; idle recovery remains below the edit panel. Notes failure explains that completed prose is preserved and Retry reuses it. Broad notes retain subtle first-occurrence links and concise English popovers. Partial prose is never displayed as a completed chapter.

## Reader redesign — Show, title section, explained expressions, swipe actions

Show / View result scrolls only as far as needed to reveal the bottom of the new explanation card (with 12px clearance above floating bars and the safe area); a card already visible does not scroll, and a card taller than the viewport aligns at its top. The status bar is dismissed before scrolling, the card is focused without scrolling, and its border pulses briefly (no animation under reduced motion).

The reader title is its own section: a bordered header card (rounded top, continuing into the text-size row) holding a small meta line (language, Chapter n of m, path name when several exist), the title, a Story actions kebab (44px), the labelled “Listen to chapter” button (reads the chapter body, as before), Previous/Chapter/Next navigation and the Story path selector when more than one path exists. Text size and furigana sit in a quiet row below it. The Story menu lists Continue story, Rewrite chapter and Copy chapter, then a divider and the destructive Remove chapter(s) and Delete this path/story entries (red); the standalone Copy icon beside Listen is retired, and the Continue story / Rewrite chapter buttons under the text remain. Selecting text in the title shows the same floating toolbar (Speak, Translate, Copy) without Explain, since explanations are anchored to story-body offsets; Android's native menu stays suppressed page-wide, so the title uses this toolbar instead.

Saved explanations are linked to the story text: each explained range gets a `mark` with a soft blue background and a solid 2px underline, distinct from the dotted glossary underline. Where explanations overlap, the newest owns the shared text. Tapping a highlight (not part of a text selection, and not a glossary word) scrolls to its explanation card with the minimal-scroll rule above and pulses it; the first fragment of each highlight is keyboard focusable (role button, Enter or Space). Each card has a labelled 44px “Show in text” button that scrolls the highlight to the middle of the screen and pulses it, so the tap affordance is an explicit control rather than a whole-card tap (long-press still starts selection; card text stays selectable). Highlights are recomputed whenever saved explanations change. They support returning to context; no learning effect is claimed.

Requesting an explanation for a selection that overlaps a saved explanation in the same chapter version first shows an app-styled confirmation naming the overlapped passages and warning that the new explanation replaces them with their follow-ups and examples. Cancel (initially focused) makes no AI request; Continue runs the request and replaces the overlapping explanations only when the new one is saved. Follow-ups on an existing card never trigger the warning.
