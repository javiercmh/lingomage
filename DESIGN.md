# LingoMage design

Design guidelines for the interface: how each screen is laid out, how it behaves and what its text must convey. Update this file in the same change as the UI. Every interaction choice here is a product assumption, not evidence of usability or learning effect; do not restate that per rule, and never present one as a finding.

**Write guidelines, not copy.** Describe what a message must say, its tone and its limits; never paste exact interface strings (labels, helpers, toasts, notifications, error text). The wording lives in the code, and tests pin it where it matters. Control and section names may be used to identify them.

## Principles

- **Visual language:** follow the App² starter (`app/src/main/assets/starter_template/css/style.css`) and host slate palette (`res/values/colors.xml`). Tokens: `--paper` #090d16, reader surface #0f172a, `--card`, `--line`, `--field`, `--ink`, `--muted` #94a3b8, `--accent`, `--accent-strong` #3b82f6, `--tint`. Card corners 18px, fields and buttons 12px, subtle borders, restrained elevation. Dark theme only; no separate reader theme.
- **Shared components:** use the shared button and field classes, not feature-specific replacements. `small-btn-quiet` (borderless) is for a secondary text action; `small-btn-strong` (accent-tinted) for a row's main action. An option that applies immediately uses the shared `switch` (a native checkbox with `role="switch"` in a `switch-row` label); a saved preference in Settings uses `settings-check`.
- **Copy:** say what learners need to decide or recover: what happened, what is preserved, what an action does, consequences they cannot infer. Prefer a clearer label, visible state or familiar symbol over instructions; keep words for meaning and consequences. Short, plain, calm; no exclamation marks or blame. Never promise what the platform cannot guarantee (background work finishing, nothing lost). Interface and glossary text are English.
- **Visual cues supplement semantics:** a collapsed disclosure shows a down chevron, expanded an up chevron, with native or equivalent keyboard behavior and announced state. Never rely on a chevron, color or icon alone for an action, error cause, destructive consequence or unavailable feature.
- **Controls:** at least 44px touch targets (also at 320px width and enlarged text), visible keyboard focus, English accessible labels, reduced motion respected. No system `alert()`/`confirm()`; confirmations are app-styled dialogs with Cancel focused first, and focus returns to the trigger on close. Render learner and model text with `textContent` or text nodes.
- **Layout:** mobile first. Combine host and browser safe-area insets, reserve space for the bottom bar and any floating bar, never cause horizontal page scrolling. Browser pinch zoom works everywhere; reader text size is a separate preference.
- **Helper spacing:** 6px from field to helper, 22px after each complete field group; label, control and helper form one group, and generic field margins must not push a helper toward the next label. Textareas have internal vertical padding.
- **Never label learning state:** no wording that calls the learner's progress continued, in progress, completed, known, unknown or mastered, and no "last studied". Time and lookup figures are factual counts.
- **Live regions:** status that changes as a result of the learner's action is announced politely, rewritten only when its text changes, and never takes focus. Figures that tick (timers, time left, practice totals) are not live regions.

## Navigation

Bottom tab bar: Create, Library, Profile, icons above labels (starter style). Settings is a separate view reached from the Profile gear. Android Back closes the topmost layer: an open note, then a panel, then the reader (returning to Library).

## Create

- **Order:** one optional multiline story-idea field (premise, genre, tone, format, domains, situations, concepts or expressions), then Reading scope, then Language and Reading level, then Generate. The learning-preferences setup notice sits beside the language fields and links to My languages.
- **Language input:** one short note inside the story group, between label and textarea and referenced by the field, says ideas may be written in English, the learning language or a mix. Say it once; never imply writing correction.
- **Reading scope:** a two-option segmented radiogroup, Scene (default) and Chapter, each at least 44px tall, with a one-line helper that follows the selection. Scope is independent of reading level. The retired Longer passage scope opens as Chapter. No word or sentence quotas.
- **Reading level:** the same per-language options as My languages (PED-004).
- **Progress:** planning, writing, then for Japanese kanji readings and vocabulary notes, which run together. Readings are listed before notes because they usually finish first, so the unfinished step stays last. Create's own progress card is the only indicator on the Create tab; a Create resumed from recovery shows the same card.
- Checkpoint recovery is one panel directly above Generate (see Generation status and recovery).

## Library

- **Header:** the Library title with a story count (showing the filtered share when a filter applies) and a compact sort select on that row, wrapping below on narrow screens. Sort is session-only: recent activity (default) or newest created.
- **Import:** a 44px secondary button beside sort, always shown (also with no stories), opens the phone's file picker for a `.lingomage.json` story file. Success adds a new story, which becomes the hero, and a toast names it. Cancelling the picker is silent. A rejected file toasts the reason (not a story file, newer format, damaged or incomplete, too large, unreadable) and nothing changes; a failed save says the stories are unchanged. The button is disabled while a file is read and gets focus back afterwards.
- **Language chips** (All plus languages present) scroll in their own row and are hidden with one language; a filter that matches nothing returns to All.
- **Hero:** the story with the latest meaningful saved activity, regardless of sort, with an eyebrow naming it as latest activity and its language. It is the only emphasized card: soft accent tint and a decorative read pill (48px high, at least 96px wide, hidden from assistive technology and during selection) inside the same single control; 18px padding, 14px between title and wrapping footer. A just-created story is the hero until other activity is saved. If no story has a valid date, the first story is a plain hero without latest-activity wording. Every other story appears once in a labelled list below. A single story shows only the hero, without the list label. With no stories, one empty state.
- **Cards:** up to two title lines, language, one date line; no prompts, practice words or topics.
- **Dates:** local calendar, relative for the last week (today, yesterday, days ago), then day and short month (year added in another year), in `<time>` elements; accessible names spell out updated or created with the full date. Show the updated date whenever saved activity is later than creation, even the same day; a new story (including one finished by a resumed request) shows its creation date. The hero shows only its relevant date; newest-created sorting shows creation dates. Missing or invalid dates omit the segment.
- **Actions:** each card has a visible 44px Actions button beside (not inside) the open control; no swipe or tray. It opens a fixed popover labelled with the story title, holding native Select, Share and Delete buttons (no `role=menu`), right-aligned under the button, flipped above near the bottom bar. Focus moves to Select; Escape returns focus to the button; outside press, scroll, resize, focus leaving, filter, sort, opening a story or bulk selection close it. Delete confirms by name and warns that all chapters, versions and explanations are permanently removed; no undo.
- **Bulk selection:** long press or Actions → Select. Checkbox marks in 44px targets replace Actions, a sticky toolbar shows the count and trash, sorting is disabled. Tapping a card toggles it; clearing the last selection exits. Trash confirms with the count and the same warning; Cancel keeps the selection. A long press is cancelled when the pointer leaves, moves past the threshold, is released or cancelled, or the page scrolls.
- **Background updates:** a request finishing in the background re-renders a visible Library, never while a selection, popover or Share dialog is open (it updates when they end). After a re-render, focus returns to the rebuilt Actions button of the story whose popover was open.

## Reader

### Frame, title and navigation

- Full-screen dialog, centered column at most 780px, no top bar.
- **Title card:** compact rounded header with a meta line (language, chapter position, storyline label when several exist; long names truncate visually, full text accessible), the selectable title, Listen immediately after the title at natural width and vertically centered even for multiline titles, and a borderless Story actions kebab at the far right (44px targets, visible focus). Long titles wrap; their box fits the widest line so Listen stays close without pushing icons out.
- **Navigation row:** one nonwrapping row of Previous, Chapter picker, Next and Aa (stroked SVG chevrons; the picker chevron points up while open). It is a separate sticky surface: when the title scrolls away only this row floats at the top safe area with a rounded border and shadow; scrolling back restores the card. Sticky styling never changes dimensions, duplicates controls, moves focus or shifts story text.
- **Panels** (nonmodal, floating, one at a time, within viewport and safe area, never shifting the story): the Chapter picker holds native Storyline (hidden for single-storyline stories) and Chapter selects plus branch-origin and continuity details. Choosing a chapter closes it and returns focus; choosing a storyline keeps it open and refreshes chapters. Aa holds a native 15–30px slider (1px steps, smaller and larger ends) and, for Japanese only, the Furigana checkbox, which shows or hides readings in both title and story; hidden readings keep their space, so toggling never moves or rewraps the text. Size previews while dragging and saves on release or committed keyboard change; the panel stays open through reflow, and the range alone disables touch panning. Opening focuses the first control; outside press, deliberate wheel scrolling outside or reader closure dismisses; Escape dismisses and restores focus without closing the reader. Reader scroll dismisses chapter navigation but not reading preferences.
- **Below the story:** equal-width Continue and Rewrite buttons, then the prompt panel when open, then status and recovery, then one Explanations section, cards in text order (by selection start, then end; the newest first for the same range).
- **Story actions menu:** Continue, Rewrite, Share (with the app's share glyph, the same as Library Actions → Share), Rebuild story memory, a divider, then destructive entries in red: remove chapters from the current one onward (or only the last), and delete this storyline (when alternatives exist) or the whole story. Keyboard accessible; Escape restores focus; scroll, resize, outside interaction and chapter change dismiss it. Pending AI work or unsaved/unreleased results disable destructive entries with a short reason.
- **Rebuild story memory:** a confirmation names the story, the captured path and the model, says it uses AI and clears the story's saved summaries, and that chapters, paths, notes and explanations stay. Cancel starts focused; the confirm button is disabled while running. A stopped rebuild keeps completed summaries and shows a recovery card offering to resume (the menu entry becomes a resume entry), also after reload, with collapsed Technical details for failures. Resume uses the captured path even if another is viewed. Pending AI work or unreadable stores disable it. Completion is confirmed with a toast and keeps the reading position.
- **Removal:** confirmation names the path and exact chapter range, explains what stays on other paths, and warns that content used nowhere else is permanently deleted. Removing chapter 1 deletes the path; removing the only path uses whole-story confirmation. Afterwards show the preceding chapter, or open the oldest remaining path at its start (keeping its name); hide the path selector when one path remains. A failed save keeps the confirmation with an inline reason and retry. No trash or undo.
- Story deletion is also available from the Library.

### Story text and vocabulary notes

- **Paragraphs:** line breaks are kept as written. Any run of blank lines shows as one half-line gap, so every story has the same paragraph spacing whichever separator the model used. Display only: saved text, offsets, copy and speech keep the original characters.
- Canonical story text has comfortable line spacing; Japanese readings are separate ruby annotations above contiguous kanji runs (compounds together; kana, okurigana and punctuation plain). Legacy mixed annotations are normalized for display only when they align uniquely; never guess.
- Russian notes show stress only on the wording from the text, in the note heading; the dictionary-form line stays unmarked. Older notes saved without form stress show the heading unmarked unless the form matches the headword.
- `spellcheck="false"` only on the story body and title, never on fields or containers.
- **Glossary links:** subtle dotted underline at the first eligible occurrence of each normalized headword/meaning pair in the displayed chapter version; later occurrences stay selectable. Alternate forms share a note; different meanings stay separate. Recomputed on reopen and chapter or version change. A Japanese match across ruby and plain segments keeps full readings, shares one popup and exposes only the first fragment as a keyboard button; all fragments activate it (PED-002).
- **Note popover:** a labelled nonmodal dialog anchored to the word; opening focuses it; Escape returns focus to the trigger. A press outside closes it, and on story text that tap only closes it (it opens no other note or explanation; controls outside the story still act); new selection, chapter or version change, reader closure or activating the same word again closes it. Each headword has a 44px Listen icon that speaks the canonical headword (no readings) in the story locale. Note controls keep story text selectable.
- **Saved explanation highlights:** each explained range is a `mark` with a soft blue background and solid 2px underline (distinct from the glossary underline); the newest explanation owns overlapping text. Tapping a highlight (not during a selection, not a glossary word) reveals and pulses its card; the first fragment outside a glossary control is keyboard focusable (button role, Enter/Space), without nesting button roles. Recomputed when explanations change.
- **Vocabulary first:** one dispatcher handles every tap, Enter and Space on story text, so nested controls fire once. Text with a vocabulary note opens the note even when an explanation overlaps; only if the activated characters also have an explanation does the note end (after a divider) with one full-width 44px button that closes the note and reveals that explanation. Explanation-only highlights jump directly. Nothing opens while a noncollapsed selection exists, or in explanation-selection mode.

### Selection

- Body text is unselectable (`user-select: none` on `body`). Selectable with the LingoMage toolbar (native menu suppressed): story body and title. Selectable with the native menu: inputs, textareas, contenteditable, explanation text (`.help-text-selectable`), the note popover and `.form-error` (so errors can be copied). Fields set `user-select: text` explicitly (caret placement in some WebViews). Everything else (titles, labels, helpers, buttons, tab bar, cards, dialogs, toasts) is unselectable.
- `js/selection-menu.js` sets the page-wide host flag from the touch target (`pointerdown`), the selection location (`selectionchange`, covering handle drags and keyboard), field focus and reader entry; a selection touching story or title always uses the LingoMage toolbar. Cache a value only after the host acknowledges it. Cancel only `contextmenu` on story and title; never prevent `pointerdown`, `touchstart` or `selectstart`.
- **Toolbar:** a compact floating popover (dark card, 14px radius, soft shadow, 44px targets) centered above the selection and clamped to the viewport, moving below with extra clearance on touch when there is no room; it repositions on scroll and resize and lifts above floating bars. Actions: Speak (icon), Translate, Define, Explain, Copy (icon); icon buttons have accessible names; below 360px the text buttons narrow their padding so all five fit on one row at 320px. Title selections omit Define and Explain (notes and explanations use body offsets). Explain is available in every environment. No Select all.
- **Action feedback:** every toolbar action runs through `runSelectionAction`, highlighting immediately on press (including touch), activating on release, ignoring cancelled presses, and showing busy state only until its own completion point: Copy when the clipboard write completes, Translate when the translator opens, Define when its note opens or fails, Explain when its AI task starts, Speak when playback ends. New actions must use the runner and define their completion point. Focus styling stays distinct from the highlight. Successful Copy clears the selection and toolbar with no app toast (Android confirms); failures keep both and show an error.
- **Translate:** sends only canonical selected text to the device translation handler after a deliberate tap; the external tool picks languages. Check availability when the toolbar appears or the passage changes (not at startup or after launch), cache confirmed availability, keep it through temporary check failures, ignore stale responses. Disabled until confirmed, without a handler, or while launching. Errors are shown without automatic retry.
- **Speak:** canonical selected text through App² speech in the story locale; disabled in browsers with a reason.

### Explanations and follow-ups

- **Define** writes one vocabulary note for the selection with the light tasks model and saves it with the chapter's notes: the word gets the same dotted underline and the note opens in the vocabulary-note popover on it. A selection inside an existing note opens that note with no request. While the request runs, the popover appears at the selection as a skeleton of the note: the selected text as heading, a × Cancel icon button where Listen will be, and two shimmering lines where the meaning will appear (a screen-reader status says "Writing a vocabulary note…"). The selected words glow and their dotted underline draws itself in, easing toward the end without completing; on success it finishes drawing and the saved note replaces the skeleton in place. Reduced motion shows a static glow and full underline. The reader status bar stays hidden while this popover is open and returns, with Cancel, if the popover is dismissed mid-request. On failure the popover shows the recovery summary and Retry; after leaving the chapter a toast reports it. A successful note clears the status bar, since the opened note is the result.
- Explain acts on the exact canonical selection. Overlapping a saved explanation in the same chapter version first asks to replace it, naming the passages and warning that its follow-ups and examples go too; Cancel makes no request, and replacement happens only when the new one is saved. Follow-ups never trigger this.
- **Cards:** separate bordered cards under one Explanations heading. The model picks a contiguous source excerpt, shown with an accent rule; only the learner's exact selection is highlighted. An optional context translation sits beneath. Initial help is one short paragraph in the interface font; story text keeps reading typography; long content wraps.
- **Show in text:** cards with valid context end their quoted surface with a transparent right-aligned footer button (accent label, upward arrow, 44px, inset focus ring) whose accessible name includes the passage (60 characters max). It scrolls the highlight to mid-screen and pulses it. Ruby stays in the excerpt; cards without context, and selection mode, show a plain quote.
- **Reveal rule** (View result, Show in text, highlight taps): scroll only as far as needed to show the card's bottom with 12px clearance above floating bars and the safe area; a visible card does not scroll; a card taller than the viewport aligns at its top. Dismiss the status bar first, focus the card without scrolling, pulse its border (none under reduced motion). Never auto-scroll to loading content.
- **More detail:** reveals a labelled one-line optional question with Cancel and submit; opening or cancelling makes no request; Enter submits; empty asks for general detail. Each question shows with its saved response; responses render paragraphs, bold, italic and inline code as DOM elements, other markup stays literal. A failed detail keeps its question.
- **Examples:** three short examples of the same function, each with the relevant form highlighted and an English translation, under an Examples heading inside the card after a divider. A speaker button beside each sentence plays it with App² speech; tapping it again stops playback. Follow-ups append in order.
- **Editing follow-ups:** a ⋮ beside a saved question opens Edit and Delete. Edit opens a prefilled multiline field with Cancel and Regenerate, warning when later content will be removed. The saved thread stays visible during generation and changes only after the new answer is saved; a failed generation can be retried from the draft, a failed save retries saving the same answer. Delete confirms removal of that question and answer; a failed delete keeps the confirmation open with the reason.
- **Loading:** a compact cancellable panel above the cards for initial help and inside the card for details and examples; saved cards stay visible. Keep clear spacing between card actions and inserted loading, error or recovery content.
- **Selecting explanations:** long-press a card's non-text surface (padding and gaps count) to select; text stays natively selectable. Checkbox marks in 44px targets; a floating bar centered 12px above the bottom safe area shows the count, trash and a mixed checkbox (partial selects all in the displayed version; all clears and exits). Tapping a surface or checkbox toggles; clearing the last exits; Escape exits; a keyboard select control appears on focus. Follow-up actions hide; scroll and focus are preserved; deleting also removes attached follow-ups. Bottom space is reserved for the last card.

### Listening

- **Title Listen:** an icon-only 44px borderless button with a bright pale-blue 28px speaker and an accessible name stating its scope. It reads the canonical title, a pause, then the full canonical chapter body in the story locale (no furigana, glossary or explanations) as sequential bounded utterances; stored prose, copy and offsets are unchanged. While playing it turns muted grey, is pressed, and its name changes to stop; pressing stops immediately and invalidates later chunks. It is disabled while a stop is pending, then restarts from the beginning. Completion, cancellation and errors restore it; a failed stop reports an error and stays retryable. Reader closure, chapter or version change, native Stop and replacement speech interrupt playback; never resume later chunks.
- **Player:** floats under the sticky navigation row from a zero-height sticky anchor; the story reserves 68px once when playback starts. Collapsed: a pill no wider than the column (286px at 320px) with Previous sentence, Pause/Resume (filled accent), Next sentence, position count, Stop and an expand chevron, 44px each. Expanded: full column width with a sentence slider, native speed select and Follow toggle; it collapses after 5 s idle or a tap in the text. The spoken sentence uses the CSS Custom Highlight API (`::highlight(speaking)`), so DOM, offsets, furigana and copy are untouched; without it the controls remain. Follow keeps the sentence below the player and turns off for that playback on a manual wheel or touch scroll (preference unchanged). Speed and Follow persist in `data/settings.json` `readingPreferences`. The player is a labelled group exposing Pause/Resume and expanded state; position is announced politely only after Previous, Next or the slider.
- All speech is disabled in browser previews, with a reason saying listening needs App². App² leaves playback controls to the app.

### Story paths (storylines)

- Paths preserve alternate histories. The interface calls them storylines; code and saved data keep `paths`. A labelled Storyline select appears only with more than one storyline.
- **Labels** are derived from saved structure by `pathLabel` (`js/story-model.js`), so older stories read the same way and saved `name` values never change: the first unbranched path is the main story; a branch is named by the chapter it branches at, numbered by saved order when several branch at the same chapter; an unbranched non-main path (after removals) is a numbered branch. Every visible mention (title meta, select, branch-origin note, removal dialogs and toasts, memory rebuild, Share, generation status) uses the label, and creating a branch is confirmed with a toast.
- Chapter navigation lists only the selected path's pinned versions. Rewrite creates and switches to a new path ending at the rewritten chapter, keeping the source path's later chapters; the fork chapter and source path show in the Chapter picker panel. Continue appends after the selected path's end even when an earlier chapter is shown.
- **Reading positions** are kept per path and saved with the story in `data/stories.json` when the reader closes or the page hides, so reopening returns to the last chapter and reading location. The location is the story character at the middle of the visible reader: reopening, rotation, text size and furigana changes put that character back at the middle, even when lines wrap differently, and the scrolls those changes cause never move the remembered location. When the middle of the view is outside the prose (title or explanations), the pixel offset is kept instead. Rotation keeps the active view, reader and open reader panels; page recreation restores the current tab and reader from its browser history entry. Path switching is disabled during generation.
- **Continue and Rewrite prompts** are labelled optional, and their placeholders say ideas may be in any language or left blank. Blank Continue follows the existing narrative; blank Rewrite retells the same main events. Both expose version-level reading level and scope; their fields are disabled during generation.

### Share sheet

- Reader Story actions → Share and Library Actions → Share open one sheet: the shared dialog panel anchored to the bottom edge (20px top corners, safe-area padding, at most 520px wide), built only from shared classes. Every action is a filled, borderless row of the same shape (56px, 18px corners) and acts immediately; no radio choice or submit button. Every share action uses the app's share glyph.
- **Header:** the story title as the heading, a short subtitle naming the choice (share or back up), and the shared × Close `round-btn`; tapping the backdrop and Escape also close.
- **Story file:** a Share row (Android share sheet) when App² can share, and a Save backup row (App² Save as, or a browser download in previews), each with its icon at the right as a 44px `small-btn` and an accessible name naming the story file. Only the first available row's icon is accent-tinted (`small-btn-strong`) and that row receives focus. Save backup is hidden only on an App² that can share but has no Save as; the group is never empty.
- **Text:** rows for the whole story (naming the storyline when several exist) and, from the reader, the current chapter (with its title), each with a leading icon and 44px icon-only `small-btn-quiet` Copy and, when App² can share, Share, whose accessible names name the scope. A switch for including vocabulary notes follows the rows; its last position is remembered in settings (`shareVocabularyNotes`, off by default) and restored on every open; a failed save shows the usual settings notice, and the switch still applies to the current share.
- **Content:** text holds the title and canonical body; whole-story text adds the story title and numbered chapter headings on the selected path; notes append a vocabulary list in glossary order; readings are omitted. A story file is never copied. Share uses only saved data and remains available during AI work.
- **Feedback:** actions are disabled while one runs. Copy keeps the sheet open: its icon becomes a check for 1.5 s and a polite live region says what was copied. A finished download closes the sheet with a toast that the file was saved; a launched share sheet closes it silently; cancellation is silent and keeps it open. Failure keeps it open with a toast naming what failed (and that the story is too large, over the host limit), never falling back to another delivery. Closing returns focus to the reader menu toggle or Library Actions button, including after deferred Library updates.

## Generation status and recovery

- **Status bar:** covers every task (Create, continuation, rewrite, explanations, details, examples) from preparation to completion and follows its initiating story. Inside that story's reader it is the reader bar; everywhere else (any tab, a closed reader, another story's reader) a page-level bar of the same design sits above the tab bar or at the bottom of an open reader dialog. Only one is visible. It sits above safe-area insets, reserves scroll space, lifts the toast and selection toolbars, and inside an open reader shares the reader bar's measured bottom space so final controls stay reachable when it wraps.
- **States:** working (with Cancel request) only while a request is live. Cancel inside LingoMage shows that cleanup is running, then clears the status and briefly confirms the cancellation. A failure offers Review without Cancel; Review opens and focuses the unfinished request's recovery controls. The error bar hides while that recovery card is visibly in the viewport (a card behind a modal or fixed navigation does not count), and returns when it is scrolled away or the learner switches elsewhere. A completed response awaiting save or release offers to save it or finish the request. After saving and releasing, the bar names the result with View result and hides after 8 seconds; hovering or focusing the bar, or a hidden page, postpones that, and returning to the app restarts the full 8 seconds. Errors, recovery, cleanup and unsaved responses never time out. Errors are dismissible. The message is a polite live region.
- **Native progress notification:** App² shows a notification while a request runs, with text LingoMage supplies (`js/ai-notification.js`): a short title naming the current step and a brief body. It never promises that the whole operation finishes while LingoMage is in the background. Native requests continue off screen; pushed completion lets an active operation validate, save and start its next step even when page timers are frozen, provided its host session remains available. Page replacement, process suspension and host limits can still interrupt work; recovery uses saved progress.
- **Results never move the learner:** a finished explanation, detail or examples request keeps the scroll offset the learner has now, not the one from when they asked. Finishing Continue keeps the viewed chapter, path, scroll and focus, refreshing counts, selectors, Previous/Next and menu labels in place; the new chapter joins the path the request started from. View result opens the story if needed (closing another story's reader first, replacing its history entry so one Back returns to Library), selects the exact result path, saves that position, then reveals the chapter heading or explanation. Rewrite switches to its new path; Create opens its story and closes any open reader first.
- **Background story context:** after a new chapter, story or alternate path is saved, and once the ready message has gone, the status bar says story context is being prepared in the background, with Cancel request, while that path's story memory is summarized. It starts only when nothing else is pending, never retries by itself, and stops quietly for any other AI action; Continue or Rewrite on the same lineage waits for it inside its Story context step. This optional preparation has no operation session, so a hidden page prevents its next request; completed summaries stay saved. Cancelling it, stopping it or pausing because the page is hidden is not reported; a real failure is a brief toast naming the reason and saying Continue will prepare it.
- **Time left:** shown only while running, never before starting. Estimates come from earlier chapters on this device: each step's median over the most similar runs (same model, effort, language and scope first), added up; Japanese notes and readings run together, so the pair counts as the longer one; Continue counts the story-context summaries it still has to make. With fewer than three similar runs for any step nothing is shown, never a built-in guess. One line under the checklist gives a single rounded figure in minutes (less than a minute near the end), and says the run is taking longer than usual once the last running step is past its usual time (also after an automatic retry or a slow reply). It never counts down seconds and is not a live region; the step timers stay as they are. Examples are not estimated.
- **Waiting note:** under the time left, while a run is live and its estimate is unknown or at least a minute, a short line says the learner can keep reading or switch apps while they wait (never a promise that work finishes in the background), then a 44px button offering a notification when it's ready. Tapping it turns on Settings → Notifications and asks for notification permission (App²'s grant, then Android's); the button is replaced by a status line saying whether a notification will come, that permission is being asked, or, if refused, that notifications are off and where to allow them in App². Permission is never asked at startup.
- **Ready notifications** (opt-in): only while LingoMage is in the background and notifications are allowed. The title says what is ready (the story, the chapter by number, or the rewritten chapter); the body is the story title. A run that stops (not a deliberate cancel) sends one saying it stopped, that finished steps are kept, and to open LingoMage to see what happened. Examples and explanations send none. On screen the ready bar is enough.
- **Chapter requests:** a compact status card beneath the edit panel with an action-specific heading, one Cancel request and the step checklist (Story context first for Continue and for rewrites after chapter 1, then planning, writing, readings and notes), from preparation (including story-context preparation and, for long stories, condensing story memory) through completion. A Continue or Rewrite resumed from recovery shows the same card; the recovery panel returns only when the run stops. Keep the current chapter visible, disable editing, retain failed prompts and completed memory checkpoints.
- **Checkpoint recovery** (saved intermediate stages): on Create directly above Generate (keeping its brief, language, level and scope after reload, with no duplicate red form error); in the reader below the edit panel beside chapter status (a running operation, fresh or resumed, uses its status card instead); also on Profile. Shows planning, prose, notes and readings status. Inputs are frozen.
  - **Elsewhere:** when the open reader belongs to a different story from the unfinished generation (or the unfinished task is a new story), a persistent notice beside the blocked generation controls says an unfinished generation needs attention, identifies the task and story title, captured destination chapter and alternate path when applicable (new stories use language and level), and offers to review it. It appears before the learner fills out another request; generation submit buttons stay disabled while another generation is unfinished. Review opens and focuses the pending operation's recovery, switching to its story or Create as needed. The recovery panel uses the same task label. Create, Profile and the owning story's reader show only their existing recovery panel; never add a second warning or a button leading to recovery on the same screen, even when that panel is below the fold. Long titles wrap; missing destinations use a saved-story fallback.
  - **Actions:** while running only Cancel request; idle offers Resume or Save / finish and Discard (Retry for a failed stage). Cancel inside LingoMage discards the unfinished attempt without confirmation, keeps form values and restores editing after cleanup; previously saved stories, chapters and story memory remain.
  - **Failed cleanup** keeps progress locked, names the failed action (removing saved progress, stopping the request, or clearing the finished request) and offers to try again; unknown or interrupted cleanup says what still needs clearing without guessing which part failed. Trying again only cancels or releases requests and removes the checkpoint; this intent survives reload and never offers Resume.
  - Partial prose is never shown as a finished chapter. A notes failure says the prose is kept and Retry reuses it. Incompatible saved definitions explain why Discard is required.
- **Other failures:** example recovery follows Explanations; explanation and detail failures offer Retry beside their source or question. Cancelling an explanation or detail removes loading and status, keeps existing explanations and the question, and briefly confirms the cancellation; if releasing the cancelled request fails, the status says so and offers Finish request (cleanup only).
- **Recovery panel layout:** ordinary unfinished work, notification cancellation, background interruptions and unavailable host requests use the normal card surface and neutral border. Save failures, failed release or cancellation cleanup, and other actionable errors keep the yellow warning surface. Working or cleanup in progress is neutral; the cross-story shortcut is always neutral. Colour supplements the reason and actions. Wrapping action row, 12px gap, 44px targets. The summary names the action, the failed stage when known and what is preserved. **Technical details** starts collapsed and is a keyboard disclosure (chevron) with bounded error text and the host error code; an unidentified failure stays unidentified. Retry requests a failed stage; Resume continues saved progress; Save response saves completed content; Finish request retries release without inference. Recovery scrolling accounts for fixed bars and bottom navigation.
- **Broken replies:** each automatic resend shows a toast naming the step (and the part, for split notes) and the attempt count, and its checklist item shows the retry count. After three resends, a fourth unreadable reply stops; the summary adds that every automatic retry was unreadable, with the usual explicit Retry.
- **Rate limits** (`usage_limit`): refused at start, the summary explains that App² limits how many AI requests LingoMage can start per minute, says how much is saved (counting note parts for split notes), and to wait a minute and Resume or raise App²'s per-app request limit. During a request, it says the provider reported a rate or usage limit, quotes the host's message, says what is saved, that Resume runs the missing parts one at a time, and that a plan quota fails again until it resets. Split notes show progress by part count; for non-Japanese split notes the stopped stage is the vocabulary notes.
- **Host failure reasons:** `response_too_large`, `incomplete`, `timeout` and specific `invalid_request` errors show the host's useful reason in the visible summary, with the same explicit Retry and preserved completed steps. Size errors concern answer text, early termination names the model's stopping reason, and timeout messages distinguish connection, streamed inactivity and overall request duration. `invalid_response` means a malformed answer; never relabel it as a size or time limit. Missing or unavailable AI models are caught before starting generation or creating a checkpoint (legacy checkpoints saved without a model explain that no model is selected and adopt the chosen Settings model on Retry). Exact host limits belong in [generation pipeline](docs/architecture/generation-pipeline.md#generation).
- **Error text:** summaries, Technical details, story-context errors, memory-rebuild errors and toasts use bounded diagnostics (at most 1500 characters of host text). Remove sensitive URLs, credentials and host identifiers without inserting `[redacted]` or other placeholder text; omit legacy markers from saved errors too. Keep the useful reason and the explicit retry instruction; if no reason remains, say only that the request could not complete. Continue/Rewrite failures before a checkpoint keep the prompt and say to submit again; memory rebuild keeps completed summaries and offers to resume. Sanitizing a message never authorizes retry or discard.
- **Background stops** use the same panel and Retry, saying earlier steps are saved and never claiming nothing was lost. Each code gets its own honest reason: `background_service` (Android could not keep background work running), `background_paused` (LingoMage was in the background when the next step was due, so it did not start), `session_idle` (released after a pause without a running step; no duration, host idle rules differ), `session_timeout` (stopped at a time limit; no duration), `not_found` (no longer available; never blame Android for stopping the app). `session_cancelled` keeps recovery because it does not establish that Cancel was pressed inside LingoMage. Only explicit in-app cancellation discards automatically; ambiguous missing requests preserve progress. Nothing resumes by itself, except that a step refused with `session_idle` before it started is started once more in a new session when the page is visible (no status shown).

Durations are written out in hours and minutes, with a floor below one minute; no charts, goals, reset or export. Disabled or story-less languages show while they have history. ## Settings

- A separate view from the Profile gear (Profile stays the current tab): a 44px back button above the heading that returns focus to the gear, then one card of sections separated by dividers, each under a small uppercase label. The footer says settings save on this device automatically. Reader preferences stay in the reader. The App² update control belongs here when added.
- **Helpers:** every option has a one-line helper naming its benefit and, when it costs extra AI requests or behaves only in some conditions, that cost or condition. A helper hides with its field.
- **Story writer:** AI model and Reasoning effort, then a collapsible **Advanced** disclosure (44px summary, chevron, closed by default) holding:
  - Light tasks model, defaulting to the story model, with a helper naming what it covers (study notes, Japanese readings, story context summaries) and what keeps the story model (story writing, examples, explanations), and its own reasoning effort, shown only when a separate model is chosen.
  - Split study notes into parallel requests (on by default): notes ready sooner on long chapters, at the cost of more requests; turn off on request or rate limits.
  - Retry broken replies automatically (on by default): an unreadable reply is sent again, up to three times, with a notice each time; each retry is another request.
  - The model helpers carry a suggested model and effort from the latest notes comparison (2026-11-25: GPT-6.2 Sol for stories, GPT-6 Luna for light tasks, both at low effort); first use preselects GPT-6.2 Sol when offered.
- **Story memory:** prepare story context in the background (on by default): Continue starts sooner, at the cost of one request per new chapter, even if never continued, and only while LingoMage is open. Turning it off stops a running background summary.
- **Notifications:** notify when a story or chapter is ready (off by default; also turned on by the waiting card's offer). The helper says it applies only while LingoMage is in the background, also when a generation stops, and that Android asks to allow notifications first; when on but not allowed, a second helper says where to allow them.

## Workspace recovery

- **Unreadable required store** (stories, settings or checkpoints): a persistent panel before the active view saying the workspace needs attention, with a selectable message naming the file and saying the original is preserved, and Retry loading (an explicit reload after external repair; never an automatic reset). Generation and settings edits are blocked; intact stories stay readable; Profile and Settings stay readable with editing disabled (disclosures, practice period and gear still work).
- **Preference save failure:** restores every affected control (text size, Furigana, speed, Follow, model and reasoning, light tasks model and reasoning, split notes, retry broken replies, language rows) without moving focus or discarding text typed in language preferences, and shows a persistent notice that the preference was not saved, naming the file and saying the previous settings apply, with Retry save (repeats the change, never reloads). In the modal reader it sits inside, fixed above the safe area and any generation bar with measured scroll space; otherwise in the page; only the visible copy is a live alert, and the reader copy goes when the reader closes. A repeat failure does not rebuild or re-announce it. With unreadable settings it offers no Retry save and says to close the reader and use Retry loading.
- Retry loading reloads only when no AI request, unsaved response or unsaved preference would be lost; otherwise it says what to finish first. Unrelated preference saves never rebuild recovery panels.
- At enlarged text and narrow widths, recovery content wraps and stays reachable without horizontal scrolling.
