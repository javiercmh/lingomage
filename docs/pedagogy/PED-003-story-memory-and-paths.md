# PED-003: Bounded narrative memory and alternate story paths

- Date: 2026-10-11
- Status: implemented; narrative fidelity and learning effects unvalidated
- Scope: continuation and rewrite in all four languages
- Evidence basis: product assumption; the event graph, compaction and event importance are evidence-informed extrapolation from AI summarization, agent-memory and narrative-comprehension research ([story memory review](../research/story-memory.md)); no evidence from learners or graded stories

## Decisions

- **Memory (version 3):** before a follow-up, each source chapter is read piece by piece into structured English memory, an event graph stored as plain JSON lists. Entries have ids: characters `C` (name, name as written in the story, description), facts `F`, open threads `T` (with the event that opened them), resolved threads (with the event that resolved them), events `E`, beliefs `B` (with the event or fact a belief gets wrong, if any), corrected beliefs (with the correcting event), condensed arcs `A`, plus uncertainties and the current situation. Each event keeps its English sentence and adds: importance (major or minor), the characters involved (`who`), earlier events without which it would not have happened (`causes`), threads it starts or advances, characters who know about it (`knownBy`) and the chapter piece it came from (`source`, stamped by code). Major means a turning point, a cause or advance of an open thread, a setup not yet paid off, a moment that defines a character or relationship, or something the learner asked for. Character beliefs must not become facts; missing information must not be invented. Japanese readings and help content are excluded. The writer receives this memory, exact recent target-language prose, the original brief, topics, preferences and the optional prompt, and is told to let characters act only on what they know or believe.
- **Changes, not rewrites:** each summary request returns only changes: `newCharacters`, `characterUpdates`, `newFacts`, `removeFacts`, `newThreads`, `resolveThreads`, `newEvents`, `learned`, `newBeliefs`, `correctedBeliefs`, `importanceChanges`, and complete `uncertainties` and `situation` lists. The model refers to existing entries by id and to its own new entries by short refs; code assigns the permanent ids, so ids never drift or collide, and entries the answer does not mention are copied unchanged. Code checks every reference before merging: links to unknown ids are dropped; a cause may only point to an existing event or one earlier in the same answer, so the graph never loops or points forward; a thread closes only when the answer names a real resolving event, and a belief is corrected only by a real event; a new character is kept only if its name occurs in the chapter piece (exactly, or for names of four or more characters as a stem without the last two, so inflected Russian and German names match); a name already in memory maps to the existing character. Dropped links are counted and rejected items listed in the record's `updateReport`; one bad link never fails the update.
- **Who knows what:** participants are always in an event's `knownBy`; others are added when the text shows they witnessed or were told, including later through `learned`, which also reaches events already condensed into an arc. Beliefs record what a character thinks, including mistaken beliefs, and stay until a named event corrects them. This covers the memory side of the knowledge check in the shelved prose candidate (see Open experiment); the writer is not checked against it.
- **Compaction:** when memory exceeds 90% of its target, a separate, visible request condenses events into arcs instead of dropping them. Code chooses what may be condensed. Events tied to an open thread, that opened one, or that a current belief contradicts are never condensed. Among the rest, minor events go before major ones; within that tier the least connected events (causes listed, events citing them, threads, threads opened or resolved, beliefs pointing at them) and then the oldest go first, and half of the tier (at least one) is condensed. The request carries up to 3000 estimated tokens of the original chapter pieces those events came from. The answer replaces the arcs and must cover every event id the previous arcs covered plus every condensed event, be shorter than what it replaces and introduce no capitalized word absent from the memory (a proxy for new names); code assigns arc ids, removes the condensed events, copies every other list and keeps who knew each condensed event in the arc's `knownBy`.
- **Continue** summarizes through the selected path's end. **Rewrite** uses memory through the preceding chapter, its recent prose and the full current chapter as revision source; a blank rewrite keeps main events and narrative role, an explicit request may change them.
- **Paths:** a rewrite starts an alternate path ending at that chapter, preserving original descendants and explanations. One Story path selector replaces independent version selection so incompatible histories are never silently combined.
- **Removal:** learners can remove a chapter and its successors from a path, or a whole path. Content shared with other paths survives; content referenced nowhere else is permanently removed after confirmation; removing the start of the last path deletes the story. One durable save with rollback; blocked while AI work or an unsaved result is pending. Path names use a persistent counter so a deleted alternate's name is never reused.

## Product defaults and limits

- Budgets (JavaScript characters, not tokens): memory has a documented target of 12000; compaction starts above 10800 and aims for 7200; a summary or compaction answer longer than 30000 is rejected as broken output. Memory grows only by merged changes, so answers stay short. Story text is budgeted in estimated tokens so each language gets comparable story content per request: summary pieces at most 2000, consumed sequentially without omission (surrogate pairs preserved), cut at a paragraph or sentence end (Japanese 「。！？」 need no following space); recent prose is the whole chapter up to 2000, otherwise its last 1000, preferring a sentence or paragraph boundary. The estimate (`estimateTokens`) counts Han, kana, Hangul, CJK punctuation and full-width characters as one, Cyrillic and Greek letters as a third and everything else as a quarter. That is about 8000 characters per piece for German and Spanish prose (the earlier budget), about 6400 for Russian and about 2000 for Japanese. The ratios are a product approximation of typical tokenizers, not measured on any model. The rewrite source is complete. The limits are code constants (`MEMORY_LIMITS`), not learner settings: a character budget is not something a learner can judge.
- Answers are read tolerantly: code fences and surrounding text are ignored, missing keys mean no change, single values count as one-item lists, flat object entries in text lists become `key: value; …`, a missing importance means minor. An answer with none of the update keys, nested entries or no JSON object is rejected with an error naming the problem. Saved memory is written by code and only its shape is checked when read.
- Two importance levels instead of a numeric score, the 90%/60% thresholds, the half-of-tier rule, the connection count as a proxy for causal connections, the name-stem rule and the 3000-token excerpt budget are product choices, not findings. Links are model judgments, not the counterfactual analyses of the cited studies.
- Memory is cached by exact ordered version lineage, chunk index, `MEMORY_VERSION` and prompt version; shared path prefixes reuse it. Summaries and condensed memories are separate records, inspectable in `data/stories.json` with provider, model and prompt provenance; summary records keep their `updateReport`; a condensed record names the summary it replaces, the event ids it condensed, the source pieces sent and the size before and after. Each is saved before its request is acknowledged, so a failed compaction is retried without regenerating the summary.
- These choices limit history growth and duplication but do not guarantee fidelity, prevent summary drift or establish improved learning. Long uncached stories need several initial requests. No live-model review of long or branched stories has been done.

## Evidence and limits

Details, access levels and limits are in the [story memory review](../research/story-memory.md). None of the sources studies learners or graded stories.

- Readers represent causal relations as a network linking non-adjacent as well as adjacent events, not as a linear chain (van den Broek & Lorch, 1993, `vanDenBroekLorch1993CausalNetworks`, [doi](https://doi.org/10.1080/01638539309544830)). Event-causality links found by an LLM improved automatic story evaluation (Sun et al., 2023, `sun2023EventCausality`, [doi](https://doi.org/10.48550/arXiv.2311.09648)), but LLMs identify causal relations poorly, worst for complex structures (Romanou et al., 2023, `romanou2023CRAB`, [doi](https://doi.org/10.48550/arXiv.2311.04284)). Hence event-to-event links checked by code.
- Replacing text with extracted entities lost detail in one graph memory (Rusu et al., 2026, `rusu2026SelectiveForgetting`, [doi](https://doi.org/10.48550/arXiv.2608.28978)); facts alone lost recall that source passages recovered (Wang, 2026, `wang2026Engram`, [doi](https://doi.org/10.48550/arXiv.2606.09900)); a graph variant added about 2% (Chhikara et al., 2025, `chhikara2025Mem0`, [doi](https://doi.org/10.48550/arXiv.2504.19413)); event-sized statements with source attribution were a strong baseline (Zhou & Han, 2025, `zhouHan2025EventMemory`, [doi](https://doi.org/10.48550/arXiv.2511.17208)). Hence events keep their sentences and sources; ids and links are added beside them.
- Checking each fact before it is written reduced memory contamination (Zhang & Li, 2026, `zhangLi2026ConsistencyGate`, [doi](https://doi.org/10.48550/arXiv.2607.22962)). Hence change-only answers, code-assigned ids and reference checks on every update. A story-writing memory built on one evidence-grounded graph with views including per-character beliefs and open developments led three writing benchmarks (Tian et al., 2026, `tian2026NarraWorld`, [doi](https://doi.org/10.48550/arXiv.2609.32401)). Hence the knowledge view on the same graph. All six are preprints.
- Rolling memory gives detail but loses coherence compared with merging chunk summaries (Chang et al., 2023, `chang2023BooookScore`, [doi](https://doi.org/10.48550/arXiv.2310.00785)); recursive summarization of summaries works for whole books (Wu et al., 2021, `wuEtAl2021RecursiveBooks`, [doi](https://doi.org/10.48550/arXiv.2109.10862)). Hence condensing into arcs rather than dropping events.
- Merging summaries of summaries can amplify hallucination; source context reduces it (Ou & Lapata, 2025, `ouLapata2025ContextAwareMerging`, [doi](https://doi.org/10.48550/arXiv.2502.00977)). Hence the shorter, coverage and no-new-names checks, code-copied lists and source excerpts sent with compaction.
- Readers' importance ratings of story events rose with an event's number of direct causal connections, which uniquely explained more variance than lying on the main causal chain (Trabasso & Sperry, 1985, `trabassoSperry1985CausalRelatedness`, [doi](https://doi.org/10.1016/0749-596X(85)90048-8)); causal connections also predicted recall and summarization (Trabasso & van den Broek, 1985, `trabassoVanDenBroek1985CausalNarrative`, [doi](https://doi.org/10.1016/0749-596X(85)90049-X)). Turning points improved screenplay summaries (Papalampidi et al., 2020, `papalampidiEtAl2020ScreenplayTurningPoints`, [doi](https://doi.org/10.48550/arXiv.2004.12727)). Hence connection counts, thread links and the major label deciding what is condensed.
- Models use information in the middle of long inputs less well (Liu et al., 2024, `liuEtAl2024LostInMiddle`, [doi](https://doi.org/10.1162/tacl_a_00638)). Hence a compact target rather than a much larger budget. Tiered memory (Packer et al., 2023, `packerEtAl2023MemGPT`, [doi](https://doi.org/10.48550/arXiv.2310.08560)) and synthesized reflections (Park et al., 2023, `parkEtAl2023GenerativeAgents`, [doi](https://doi.org/10.1145/3586183.3606763)) are precedents for keeping condensed and detailed memory side by side.

## Compatibility

Legacy stories derive paths lazily from version-source and predecessor links (same-chapter rewrite links traced to their original predecessor). Without provenance, the saved selected sequence is used and continuity is marked uncertain. No bulk migration; all stored chapters, versions and help are preserved. Memory version 1 records stay in `data/stories.json` as provenance but are not reused: the first Continue or Rewrite after a memory version change summarizes the path again in the current format (version 3).

## Open experiment

A candidate prose writer (development only) internally checks who knows what, possession and ownership, character and object location, chronology and unresolved events, within the same request and schema. It is not shipped; it waits for notes-prompt selection and a separate prose evaluation. See the [controlled comparison](../evaluation/generation-tests/notes-prompt-experiment/README.md).

## Revisit when

Live-model review of long and branched stories shows drift or omissions, or compaction often fails its checks; then revisit budgets, thresholds and instructions. If condensed arcs drift despite source excerpts, raise the excerpt budget or condense fewer events at a time. If models often produce links that code drops (see `updateReport`), simplify the update format. If the name check rejects faithful arcs often, replace it with a stricter structured check.
