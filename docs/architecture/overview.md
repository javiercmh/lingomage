# Architecture overview

What the app is made of: platform, modules, version constants and tests. Architecture docs: [overview]() · [data and storage](data-and-storage.md) · [generation pipeline](generation-pipeline.md) · [learner tracking](learner-tracking.md) · [safeguards](safeguards.md). Interface rules: [`DESIGN.md`](../../DESIGN.md).

## Overview

- Dependency-free HTML/CSS/JavaScript App² subapp at the repository root; no build step, framework, native code or production server. Historical Kotlin is in Git; the [safeguard audit](safeguards.md) records what was adopted.
- `dev_server.py` (Python 3.12+) serves the workspace for browser testing with deterministic `--mock-ai`, or development-only `--chatgpt` through the Codex CLI login.
- Prompts: every AI prompt and `PROMPT_VERSION` live in `js/prompts.js` (story and chapter prose, Explain/More detail/examples, language plan, vocabulary notes, Japanese readings). Only the story-memory prompts stay in `js/story-memory.js` with their own versions.
- Versions: prompt `PROMPT_VERSION` in `js/prompts.js`, safeguards `SAFEGUARD_VERSION` in `js/learning-validation.js`, memory `MEMORY_VERSION` and memory prompts `SUMMARY_PROMPT_VERSION`/`COMPACTION_PROMPT_VERSION` in `js/story-memory.js`, app `version` in `manifest.json`.

## Modules

- `js/bridge.js`: the only caller of host APIs (`ai`, `speech`, `translation`, `share`, `updates`, `selectionMenu`, files). App² owns AI configuration and credentials (App² Settings → AI), speech, translation and update installation; the workspace never stores credentials or request headers.
- `js/app.js`: start-up and composition: constants, `state`, stores and settings persistence, the generation status bar, background story context, running and applying generation operations, Continue/Rewrite, models, and Library selection mode. It creates the screen modules below in its original top-to-bottom order.
- Screen modules (former `js/app.js` sections, moved verbatim): `js/reader-view.js` (opening the reader, chapters and paths, navigation, panels and preferences, note cards, reading location), `js/reader-help.js` (selection toolbar, listening, note activation, explanations, follow-ups, examples, saved help, the chapter status card), `js/reader-player-ui.js` (sentence player controls), `js/create-flow.js` (Create: generate, cancel, saved-progress panel, saving the new story), `js/generation-status-ui.js` (waiting screens, estimates, ready notifications), `js/library-view.js` (Library cards, Story Actions, long press, deletion), `js/share-dialog.js` (Share and Import story), `js/stats-view.js` (Stats and Most looked up), `js/language-settings.js` (learning-language rows).
- Screen-module convention: each exports one `create…(deps)` factory whose body is the section's code; `js/app.js` calls it where the section used to be, so listeners and start-up run in the same order. One exception: `createReaderPlayerUi` is called just before `createReaderHelp` (originally the player section sat inside the help section), so the player's listeners register before the selection listeners; they share no target and event type. Per-boot state stays inside the factory (the test harness boots `js/app.js` several times per process). Bindings that `js/app.js` reassigns are read through accessors (`currentPipeline()`, `currentReaderGeneration()`, `currentBackgroundRun()`) or changed through setters (`setPlaybackContext`, `setCreatingStory`, `setReaderViewport`, `setRestoringPathPosition`); functions created further down are passed as call-time wrappers `(...args) => name(...args)`, and objects created further down need a forwarder. Keep multi-line template literals out of these modules (see `tests/support/app-source.cjs`).
- `js/workspace-storage.js`: store definitions, validators and missing/valid/invalid states.
- `js/story-model.js`: legacy chapters and exact-version paths. `js/story-memory.js`: bounded lineage-specific memory. `js/generation-controller.js`: idempotent final application. `js/generation-pipeline.js`: staged generation. `js/generation-errors.js`: failure categories and recovery wording.
- `js/reader-panels.js`: nonmodal panel positioning, focus and listeners. `js/paragraph-gaps.js`: shows blank-line runs in the story as one short paragraph gap (display only). `js/selection-menu.js`: host selection-menu routing. `js/settings-feedback.js`: preference-save notices and the reload guard.
- `js/ai-session.js`: the `ai.start` wrapper and operation sessions. `js/ai-notification.js`: task-specific `title`/`body` for every `ai.start` (presentation only; never affects prompts, versions or saved data).
- `js/generation-timing.js`: what each generation step took and estimates for the next run (pure helpers).
- `js/usage-tracker.js`, `js/usage-stats.js`: time tracking. `js/consultation-signals.js`, `js/reading-exposure.js`: lookup history and probable reading. `js/library-activity.js`: Library ordering and dates.
- `js/story-share.js` provides pure canonical text formatting, full-record export, story-file import validation and re-identification, and injected delivery selection. `js/app.js` supplies a saved snapshot, dialog and browser download; only `js/bridge.js` accesses `AppShare`.
- Dependencies are injected so tests import production modules.
- Tests that check or evaluate app source read `js/app.js` plus the screen modules through `tests/support/app-source.cjs`, which strips each factory wrapper and indent so the text matches the former sections. A new screen module goes in `manifest.json` (`files` and `app2Update`) and in that helper's `MODULES`.

## Testing

- `python3 scripts/check.py` (Node 22.12+, Python 3.12+) runs every Node and Python test.
- `python3 scripts/browser_smoke.py` prints a runner URL; Run smoke checks needs its disposable-workspace marker and offline mock. It covers the four language flows, notes, reopening, continuation and rewrite, cancel/reload/resume, malformed and blank stores with Retry loading, unreadable settings and injected settings write failures. `tests/browser/inspect.html` gives screenshot fixtures for recovery and write-failure states. `tests/app-startup.mjs` boots `js/app.js` against a stub DOM.
- Mock fixtures establish interface and contract behavior only. Host (Android) behavior is tested in App², not here; live-model evidence is in the [generation test results](../evaluation/generation-tests/results.md).
